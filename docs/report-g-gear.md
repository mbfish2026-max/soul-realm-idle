- gear.js：随机掉落、穿脱替换、等级限制、仓库移动、锁定、筛选排序、批量分解灵晶、锁一词条重铸、十级强化、属性汇总及战力上限、六槽迁移。词条不重复，保留词条不扣改，失败不扣费。套装计数排除两散件，终极含强化/词缀的装备战力封顶为同等级同红品普通八件加两散件基准的 1.8 倍。

- ui.js / gear.css：人物左五右五格、装备详情、强化重铸、分解确认、仓库品质/部位/种类/锁定筛选、排序与批量选择。复用原 UI 弹层，点遮罩关闭。人物用既有 hero_idle 资源，无新增图片。仓库保留精魄吸收与兽卵孵化入口。

## 集成接线（必须由对应路完成）

普通 script：names.js → 原 data/core/systems → ui/tabs.js、ui/bag.js 及其他原 UI → features/gear/data.js → features/gear/gear.js → features/gear/ui.js；加载 features/gear/gear.css，UI 定义完成后调用 SR.gear.install()（幂等）。提供 SR.ui.gear(state)、SR.ui.warehouse(state)，原背包自动追加装备/仓库按钮；也可使用 SR.ui.show('gear'|'warehouse') 挂入口。无需额外定时器。应在 UI mount 前 install。

A 路：core/loot.js 简易装备生成替换为 SR.gear.roll(level, SR.rng)，调用方仍负责入包。存档 v2 的核心版本检查、create 默认值与 migrations[1] 需 A 修改，迁移内调用 SR.gear.migrate(s) 再置 v=2，保留旧键读取；当前核心只接受 v1，G 没有擅自升级 state.v 导致下次载入被拒绝。install 会迁移当前与 save:loaded 的装备槽位，迁移幂等且冲突物入仓不丢失。

B 路：SR.stats.hero(state) 最终 power/teamPower 前，将 SR.gear.statBonus(state) 的 atk/def/hp/spd 加入 out；不要重复累加 bones。角色主页面如需统一展示，可链接装备页或嵌入其渲染结果。本路只提供独立人物装备页，不修改 ui/hero.js。原背包的装备详情表现仍需 B 统一采用本路接口，仓库页已提供十部位详情与管理。

集成路：加载上述脚本/样式并 install，检查资源 URL 与正式入口一致。接口追加在 docs/interfaces.md 的 g-gear-v2 小节，其规则覆盖早先六部位提案。
