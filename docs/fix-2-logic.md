# 第二轮 logic 修复

分支：`fix2-logic`，基于 integration；仅修改 logic 所属实现、测试和本记录，未 push。

## R2-03 · P2 · 异步离线接线（逻辑完成，界面配合待接）

- 改动：`core/idle.js` 的启动、节流长间隔、visibility 恢复均使用 `claimAsync`。结算期间禁止 tick 和 hero:changed 触发开战；重复启动/恢复共用当前任务；结束保存后仅在前台且 idle 仍运行时开战；异常保留已提交的时间游标，暂停等待恢复重试。隐藏/停止发生在分块间也不会误开战。
- 接口：`idle.start()` 返回结算 Promise；`idle.settling()` 查询状态；`offline:status` 携带 `{claiming, progress, result?, error?}`，供 view 连接进度和最终收益弹窗。`offline:reward` 仍仅最终发一次。
- 验证：`core_idle_async.test.js` 覆盖启动、进度、防重入、后台完成、前台恢复、异常重试、停止中结算；原 idle/auto 测试改为等待真实异步完成。
- view 协作：`main.js` 的启动代码仍同步检查局部 offline 变量，需 await `idle.start()` 或监听结算结束再显示收益；进度/异常展示也需接 `offline:status`。本路不修改 main.js/ui。未将界面进度或浏览器长任务检查声称为已完成。

### R2-03 补充验证与容量截断

- `battle.start` 在异步结算分块间也拒绝开战；同步 claim 在异步任务期间拒绝重复领取。手动保存只写已处理游标，避免把尚未结算的离线时间提前吃掉。
- `battle.tick` 返回实际处理毫秒，离线汇总包含块内满仓中止时间；最终 idle 不对满仓状态重新开战。回归覆盖满仓、游标、防重复和分块中保存。
- `python3 tools/sim/offline-browser.py`：真实 WebKit 390×844、99 级寒川 12h **夹具**，经正式 idle.start 结算。248 次心跳、249 次状态通知，最大心跳间隔 23ms，收益事件 1 次；结算期间并发战斗 false；满仓截断 28352.857s 后保持停战。pageerror / console.error / HTTP≥400 均 0。此为桌面夹具响应性证据，不是实体手机性能或完整 UI 验收。

## R2-01 · P1 · 连续养成平衡

- 问题根因：旧经验只按楼层给，与跨图敌人强度不匹配；首环分支与首宠角色还会改变整个人物的攻击倍率；普通掉落密度使低频整理玩法大量时间停在容量上限。
- 改动：移除由首环/首宠决定的隐式整人物攻击倍率，改为 35 级后的连续基础成长。40 级前保留击杀升级节奏；40 级后按运行中的战斗时长（含波间恢复）积累修行经验，在真实击杀时统一入账，另保留 5% 原击杀经验奖励。停止、满仓不积累；不直接修改等级、不根据模拟结果赋满配。经验曲线基数 44000，修行基准每级 4320 战斗秒。
- 离线规则：12h 封顶与 70% 战斗时间保持；经验有明确的 1.35 倍静修补偿，掉落/灵晶/培养资源不享此倍率。离线经验报告按实际授予经验统计，包含修行部分，避免旧的楼层公式少报。
- 资源：普通精魄概率 30%→12%、兽卵 2.5%→1%、装备 7%→4%；首领精魄/兽卵保底不变，容量上限与锁定保护不变。降低重复物整理压力，不扩大存档上限。
- 模型：继续使用自然收集、吸收成败、装备选择和培养/技能消费；按真实出战上限孵化第三宠。新增 `--cultivation=full`，使用实际强化、蜕变及秘境接口进行敏感性检查。`tools/sim/tune.js` 改为多种子验收入口，删除旧的读取历史报告并改写游戏数据的调参循环。
- 验证：两个种子 4200/4201 × 六职业 × 低/中/高整理频率 × 在线/离线，**72/72** 到达 99 级且已击败熔脊末层首领，全部在目标内：在线 **67.167–69.683h**，离线 **71.167–75.317h**。六职业高投入在线/离线 full 养成敏感性检查 **12/12** 达标：**67.000–72.900h**；每场均实际完成强化、蜕变和秘境胜利，非只打开开关。18 个分职业验收进程退出码全部为 0。
- 证据与复现：`tools/sim/fix-2-results.json` 保存 84 场结果、命令、输入哈希和浏览器夹具结果。完整基础矩阵可运行 `node tools/sim/tune.js --seeds=4200,4201 --hours=160 --assert-target=true`；敏感性运行 `node tools/sim/skills.js --hours=160 --investment=high --cultivation=full --assert-target=true`。
- 回归：`core_practice.test.js` 覆盖真实击杀结算、停止无经验、离线经验准确汇总、游标防重复与满仓截断；`node --check` 全部跟踪/新增 JS、`node tests/run.js` 全部通过（41 个测试文件）。
- 边界：模型会在按频率整理后恢复 battle.start，仍不代表 view 的 R2-02 满仓交互已经修好；本路未修改 view，也未把原样 `tools/e2e.py` 称作通过。试炼门槛仍按 R2-08 列为未完成；这批平衡对应当前可达玩法与明确的模拟终点。
